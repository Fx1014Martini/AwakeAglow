# V2 视觉对齐差异清单

## 依据

- `xingxun-responsive-prototype/assets/reference/01-14-*.png`：逐屏视觉事实来源。
- `xingxun-responsive-prototype/docs/DESIGN.md`、`PAGE-SPEC.md`、`COMPONENT-SPEC.md`、`VISUAL-QA.md`：布局、组件状态、尺寸和验收规则。
- `awakeaglow-miniprogram-v8/docs/V8-VISUAL-FIDELITY.md`、`design/tokens.json`、`components/xx-*`、页面 WXSS/WXML：原生小程序的已验证落地实现。

## 现状差异

1. V2 首页和菜单仍使用旧的 `recommend-hero` / `result-card` 结构，主推荐卡没有 V8 的海报卡比例、圆角、渐变层级和分数排版。
2. V2 关键页面使用 `app-icon`/字符符号混合表达，未完全复用 V8 的主题图标资产，导致导航、收藏、筛选和 CTA 的视觉重量不一致。
3. V2 详情页的 Hero、配方/雷达组合卡、步骤列表和相似推荐没有采用 V8 的连续纵向节奏；海报数据也没有统一走本地 4:5/4:5 视觉资产。
4. V2 的短主题变量此前没有完整映射，部分组件的背景、文字、边框和阴影可能退回浏览器默认值或咖啡主题。
5. V2 的双主题色值与 V8 token 存在偏差，鸡尾酒模式的深色表面、勃艮第红和金色层级不够稳定。

## 本轮目标

- 复用 V8 已验证的 `xx-drink-card`、图标、海报和页面视觉规则；只改数据字段和事件适配，不重新发明视觉组件。
- 首页、菜单、详情、对比、收藏、我的和百科统一使用 390 CSS px 设计节奏、38rpx 页面边距、底部安全区和 4 个根导航项。
- 以截图为验收目标：无字符 Emoji 核心图标、无卡片无背景、无主题串色、无图片拉伸、无底栏遮挡。

## 取舍与未经证实假设

- 取舍：V8 的视觉组件优先于 V2 当前组件命名，保留 V2 的 app_v1 Service、页面逻辑和数据契约；这样能降低业务回归风险，但会增加一次事件/字段适配成本。
- 未经证实假设：V8 的图标和海报资产可直接作为 V2 的小程序本地资源使用，最终包体和微信开发者工具的图片渲染仍需现场验证。
