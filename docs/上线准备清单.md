### 1.2 酒类信息展示的类目与资质（微信官方规则调研）

**产品形态前提**：醒醺为**咖啡/鸡尾酒配方信息与推荐决策工具**，无交易、无支付、无商品售卖（代码实况：`openapi/openapi.yaml` 9 个端点均为查询/收藏/偏好类，无任何订单/支付端点）。

**微信官方规则（2025-2026 现行，来源见文末）**：

1. **「商家自营-酒类」类目仅在提供酒类在线销售及配送服务时需要**。资质要求（3 选 1）：
   - 《食品生产许可证》（经营项目含酒类）或《食品经营许可证》（含"预包装食品销售"）；
   - 仅销售预包装食品的：《预包装食品销售备案凭证》；
   - 口岸商店：《国境口岸卫生许可证》。
   （来源：小程序开放的服务类目 https://developers.weixin.qq.com/miniprogram/product/material.html）
2. **类目必须与实际服务一致**，否则属常见拒绝情形：「5.7.2 商品售卖类目不符（售卖食品、酒等未申请相关类目）」与「5.7.3 内容展示类目不符」（来源：小程序运营规范 https://developers.weixin.qq.com/miniprogram/product/）。
3. **未成年人保护红线**：运营规范 3.11 要求「小程序应按照国家法律法规等规定……对可能涉及不宜未成年人接触的内容或服务予以提醒或处理，保护未成年人权益」——这是年龄门禁（1.3）的平台规则依据。
4. 官方类目常见问题口径：涉及**酒类在线销售及配送**才建议选择【商家自营-酒类】（来源：微信开放社区类目 FAQ https://developers.weixin.qq.com/community/minigame/doc/00028a022c04e04b2f34cc9c166809）。

**结论与建议（待用户拍板）**：
- 因**无销售行为**，原则上不需要《食品经营许可证》与「商家自营-酒类」类目。
- 类目候选（提审时按微信后台实时类目树为准）：【工具】或【生活服务-信息资讯】类信息展示类目。
- 风险提示：鸡尾酒内容占比 2/3（254/384），审核员可能按涉酒内容从严把握；**若微信审核要求补酒类类目资质而无法提供，备选路径是弱化酒类展示或暂缓酒类内容**——此项需用户决策（见 §5 决策表 D4）。

### 1.3 年龄门禁

**代码侧现状**：
- `miniprogram-v2` 已实现全局鸡尾酒年龄门禁（`lib/age-gate.ts` + `pages/age-gate`），发布前仍需在微信开发者工具核对确认态持久化与深链回跳。
- 年龄门禁实现由并行任务承担，本文档描述其预期形态。

**预期实现位置（与实现任务约定口径）**：首次进入鸡尾酒模式时的全屏门禁弹层/页面，确认结果经 `wx.setStorageSync` 持久化（与 `stores/index.ts` 的 `STORAGE_KEY` 同一存储体系）；未成年用户进入「未成年人模式」（仅咖啡内容，不展示鸡尾酒）。

**审核注意事项**：
- 门禁必须**先于**任何酒类内容可见（含首页鸡尾酒推荐位）；审核员首次冷启动路径必须能看到门禁。
- 门禁确认不可被轻易绕过（不能仅靠本地标记而内容已在页面渲染）。
- 建议同时在鸡尾酒内容页保留「理性饮酒 · 未满 18 周岁请勿饮用」提示条（旧版 miniprogram 已有同款文案）。
- 提审备注中主动说明年龄门禁机制，降低「涉未成年人」驳回概率。

### 1.4 服务器部署：公网 HTTPS + ICP 备案域名

**硬性要求**（微信平台规则）：
- 自 2023-09 起，**小程序必须先完成 ICP 备案**方可上架（微信公众平台小程序备案功能）。
- 正式/体验版（开启 `urlCheck`，当前 `project.config.json` 已设 `"urlCheck": true`）下，`wx.request` 目标域名必须：已备案 + HTTPS（TLS 证书有效）+ 在微信后台配置为 request 合法域名 + 不使用 IP/localhost。
- 当前代码 `config/app-config.ts` 的 `apiBaseUrl` 为 `http://127.0.0.1:8020/api/v1`（开发值），上线前需替换为生产域名。

**待用户提供**：

- TLS 证书（可用云厂商免费证书）；
- 反向代理（nginx/caddy）终结 HTTPS → 本机 :8020。

### 1.5 微信后台合法域名配置清单

| 配置项（微信公众平台 → 开发管理 → 开发设置 → 服务器域名） | 是否需要 | 说明 |
|---|---|---|
| **request 合法域名** | ✅ 必须 | API 域名，如 `https://api.<备案域名>` |
| **downloadFile 合法域名** | ⚠️ 视图片方案 | 若图片走与 API 不同域名的 CDN，需添加该域名；若图片与 API 同域（BFF /static 直供）且 image 组件直接引用，image 标签不受此限，但 `wx.downloadFile` 预下载场景需要 |
| **uploadFile 合法域名** | ❌ 不需要 | 产品无任何上传功能 |
| **socket 合法域名** | ❌ 不需要 | 无 WebSocket |
| **web-view 业务域名** | ❌ 不需要 | 无 web-view 页面 |

注：当前 wxml 均用 `<image src="{{item.imageUrl}}">` 直接引用（menu/detail/compare/favorites/profile/home 六处），image 组件加载**不经过** downloadFile 合法域名校验，但图片域名仍需在小程序可访问的公网范围内；若后续引入图片预下载，再补 downloadFile 域名。

### 1.6 图片托管

**代码实况**：`workspace/db/awakeaglow_v6_simple.db` 中 **111 条产品图片已本地 WebP 托管**（BFF `/static/products/{code}/{card,poster,thumb}.webp`），**273 条过渡保留 Wikimedia 外链**（原图下载受 Wikimedia 429 限速，部分未完成；后台可续跑 `workspace/fetch_images.py` + `derive_images.py` + `import_data.py` 增量补全）。

- BFF 侧 `/static` 挂载点已就绪（`server/app_v1/main.py:34,64-71`，环境变量 `AWAKEAGLOW_V1_STATIC_DIR`，默认 `server/assets/images`，目录不存在时优雅跳过），但库内 URL 尚未切换。
- Wikimedia 外链风险：**国内访问不稳定、无 SLA、版权标注义务（CC BY-SA 需署名）**，不可作为生产图片源。

**过渡方案**：图片下载入库 → 改为 BFF `/static` 直供相对路径（与 API 同域，免额外域名配置）。
**生产建议**：对象存储 + CDN，配置项清单：

| 配置项 | 说明 |
|---|---|
| 存储桶（如 腾讯云 COS / 阿里云 OSS） | 384 张主图 + poster，预计 <500MB |
| CDN 加速域名 | 需 ICP 备案（如 `img.<备案域名>`）；若与 request 域名不同需加 downloadFile 合法域名（仅预下载场景） |
| 访问权限 | 公有读（图片无敏感性）或带签名的防盗链 |
| 缓存策略 | 内容不可变发布（release_code 机制），建议 CDN 长缓存 + 文件名带内容哈希 |
| 微信侧 | 若用 downloadFile 预加载，把 CDN 域名加入 downloadFile 合法域名 |

**代码侧改动量**：仅需把 `card_json.imageUrl` 批量替换为新域名前缀（图片管道任务），前端零改动（`imageUrl` 为 `uri-reference`，契约 `openapi.yaml` L321）。

### 1.7 隐私协议与用户数据声明

**代码实况（收集范围实况）**：
- `app.json` 无 `permission`、无 `requiredPrivateInfos` 字段（实况：未使用定位/相机/录音/蓝牙等任何隐私接口）。
- 不调用 `wx.login` / `getUserProfile` / 手机号等身份接口（全仓检索确认）。
- 用户态仅基于 **`X-Install-Identity` 匿名身份头**（≤64 字符，`server/app_v1/repositories/drinks.py:30`；契约口径见 `openapi/DECISIONS.md §5`）：已由 `App.onLaunch` 调用 `initInstallIdentity`（`lib/identity.ts`）动态生成 UUIDv4 并经 `wx.setStorageSync` 持久化，覆盖 `config/app-config.ts` 的开发占位值（`app.ts:26-30`）。
- 收集范围 = 收藏列表、浏览历史、偏好筛选（过敏原/口味），全部与该匿名 ID 关联，**不采集任何可识别个人身份的信息**。
- 本地存储仅 `wx.setStorageSync`（store、HTTP ETag 缓存、数据源开关），非隐私敏感接口。

**待办（微信后台）**：
- 微信公众平台 → 设置 → 服务内容声明 → **用户隐私保护指引**：按实际填写。因未使用隐私敏感接口，核心声明为「不收集个人信息；收藏/历史仅与设备本地生成的匿名标识关联」。
- `requiredPrivateInfos`：**当前无需配置**（该字段仅在使用地理位置等接口时必填）；若后续引入定位推荐再补。
- 注意：2023-09 后若代码调用了隐私接口需 `wx.requirePrivacyAuthorize` 流程；当前实现未触发该链路。

## 2. 部署方案（server/app_v1）

### 2.1 可配置项清单（全部来自代码实况，无臆测项）

| 环境变量 | 默认值 | 说明 | 代码位置 |
|---|---|---|---|
| `AWAKEAGLOW_V1_DB` | `workspace/db/awakeaglow_v6_simple.db`（仓库相对路径） | SQLite 库路径 | `server/app_v1/repositories/drinks.py:26-28,46-47` |
| `AWAKEAGLOW_V1_CORS_ORIGINS` | 本地开发来源（localhost:8080/5173/3000 等 6 项） | CORS 白名单，逗号分隔 | `server/app_v1/main.py:35-40,50-58` |
| `AWAKEAGLOW_V1_STATIC_DIR` | `server/assets/images` | /static 图片目录，不存在时跳过挂载 | `server/app_v1/main.py:34,64-71` |

实测环境：Python 3.13.3，fastapi 0.136.1，uvicorn 0.46.0。
说明：`main.py` 中**无**端口/主机/log 级别的环境变量读取（端口与日志由 uvicorn 启动参数控制），`docs_url=/docs` 为硬编码开启（生产建议反代层屏蔽 `/docs`）。

### 2.2 常驻进程建议

```bash
# 单进程 uvicorn（推荐起点：SQLite 单文件 + 内容只读发布，单进程足够）
uvicorn server.app_v1.main:app --host 0.0.0.0 --port 8020 \
  --workers 1 --log-level info --access-log

# 进程守护（systemd 或 supervisor；示意）
# WorkingDirectory=/opt/awakeaglow/v6
# Environment=AWAKEAGLOW_V1_DB=/opt/awakeaglow/data/awakeaglow_v6_simple.db
# Environment=AWAKEAGLOW_V1_CORS_ORIGINS=https://<web前端域名>（无浏览器端消费可省略）
# Environment=AWAKEAGLOW_V1_STATIC_DIR=/opt/awakeaglow/data/images
```

注意：SQLite 以 WAL 模式 + 线程本地连接运行（`drinks.py:36-44`），多 worker（gunicorn）技术上可行但每个 worker 独立缓存 `_release_cache`，单进程最简。若未来确需多 worker：`gunicorn -k uvicorn.workers.UvicornWorker -w 2 server.app_v1.main:app`。

### 2.3 持久卷

- 挂载数据目录（如 `/opt/awakeaglow/data`），包含：
  - `awakeaglow_v6_simple.db` + WAL 伴生文件 `-wal` / `-shm`（三者必须同目录，勿拆开备份）；
  - 静态图片目录（若走 1.6 过渡方案）。
- 容器部署时该目录必须为持久卷（volume），否则重启丢数据。

### 2.4 健康检查

BFF 已内置两个探针（`main.py:154-171`）：

| 端点 | 语义 | 用途 |
|---|---|---|
| `GET /health/live` | 进程存活（恒 200 `{status: alive}`） | LB/k8s liveness |
| `GET /health/ready` | 就绪：DB 可读且 meta 表有 release_code；无发布返回 503 `no_release` | LB/k8s readiness、上线自检 |

建议：反代（nginx）对 `/health/*` 免日志或单独采集；上线发布内容后先打 `/health/ready` 确认 `content_release` 与 `total=384` 再放流量。

### 2.5 日志与备份

- **日志**：`logging.basicConfig(level=INFO)`（stdout）+ uvicorn access log；建议容器/systemd 收敛到文件后按天轮转；排障可用响应头 `X-Request-Id`（每请求注入，`main.py:100-104`）。
- **SQLite 备份**（WAL 模式勿直接 cp 主库）：
  ```bash
  sqlite3 awakeaglow_v6_simple.db ".backup '/backup/awakeaglow_$(date +%F).db'"
  ```
  - 策略建议：每日一次 `.backup` + 每次内容发布（release_code 变更）前手动备份；保留 7-14 份。
  - 内容不可变发布模型下数据变化极少（仅 user_profile/user_favorite/user_history 用户态写入），备份压力小。

1. **类目不符**（5.7.2/5.7.3）：被认定为涉酒经营而无类目资质 → 对策：提审备注明确「无交易/无支付/信息展示」，页面不出现价格、购买、下单字样。
2. **未成年人保护缺失**（3.11）：无年龄门禁或门禁形同虚设 → 对策：门禁先于内容 + 理性饮酒提示条 + 未成年人模式。
3. **诱导饮酒倾向文案**：推荐语不得出现劝酒/拼酒/豪饮暗示；现有数据含「理性饮酒」提示（内容基线良好），提审前全量扫一遍鸡尾酒文案。
4. **域名问题**：request 域名未备案/非 HTTPS/未加白名单（体验版真机阶段即暴露）→ 提审前完成 §1.4/1.5。
5. **隐私指引未配置**：未填写用户隐私保护指引导致提审被拒 → 先配置再提审。
6. **内容不完整**：空态/占位符页面会被拒；当前 384 条内容字段完整（22 条硬校验基线），上线前确保 `/health/ready` 的 `total=384`。
