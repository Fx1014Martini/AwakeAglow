# V6 小程序前端主导升级验收报告

## 结论

代码与接口层达到可继续进入微信开发者工具验收的状态。小程序前端以 `xingxun-responsive-prototype` 的视觉与交互为基准，以 V8 的组件/设计令牌为适配参考，真实数据接入 `server/app_v1` 的 `/api/v1` 与 `awakeaglow_v6_simple.db`；BFF 与数据库只为前端动态流程补齐必要能力。

## 本轮交付

- RealService 已接入 `server/app_v1` `/api/v1`：首页首屏、搜索/筛选、详情、相似、推荐、对比、收藏、历史、偏好。
- 偏好编辑完成底部抽屉交互，通过 `PUT /api/v1/profile/preferences` 写入 `user_profile`，按匿名安装身份持久化。
- 详情加载由 BFF 的 `GET /api/v1/drinks/{drinkId}` 自动写入浏览历史，个人页可读取最近浏览。
- 统一咖啡奶类用户语言：BFF 的“含乳”在小程序 UI 适配为“牛奶”，燕麦奶/豆奶等具体植物奶保持原值，筛选与详情一致。
- 主题变量补齐短变量兼容层，首页、菜单、详情、个人和年龄门禁均随咖啡/鸡尾酒主题切换颜色、背景、边框与阴影。
- 百科页分类入口改为可展开的知识内容面板，不再提示“即将上线”。
- 视觉重做：复用 V8 `xx-drink-card` 卡片、主题 Logo、主题图标与核心 Hero 海报资产；首页、菜单、收藏、详情、对比的卡片结构与 V8 参考图重新对齐。
- 详情 Hero 改为左文右图、海报优先；收藏页改为列表卡 + 横向紧凑推荐；主题短变量与图片资源链路补齐。

## 依据、契合度与取舍

- 依据：HTML 高保真原型、V8 小程序交付件、`openapi/openapi.yaml` 与 `server/app_v1` 契约、当前简化库 384 条产品数据。
- 契合度：前端页面继续只依赖 Service/契约层，v1 的物化卡片、偏好、收藏和历史不泄漏到页面；用户态能力通过匿名安装身份保持无登录可用。
- 取舍：沿用 `user_profile` 的偏好 JSON 字段而不新增表，保持 app_v1 简化数据库契约稳定；v1 的详情接口自动记录历史，前端不重复写入。
- 未经证实的假设：当前尚未在微信开发者工具真机/模拟器中完成逐屏截图验收，合法域名、远程图片域名、分包路径和真实设备安全区仍需按发布环境复核。
